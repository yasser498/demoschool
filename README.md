# SchoolPulse — غرفة العمليات المدرسية الذكية

مشروع تجريبي مدرسي مستقل بالكامل.

## ما الذي يقدمه؟
- لوحة حالة المدرسة اليومية.
- مركز البلاغات: صيانة / سلامة / تقنية / مرافق / نظافة / سلوك.
- أولوية البلاغ + SLA تلقائي.
- تسجيل غياب المعلمين.
- إنشاء احتياجات تغطية تلقائيًا من الغياب.
- إسناد وتحديث تغطية الحصص.
- المهام والتكليفات اليومية.
- سجل التأخر الطلابي.
- سجل زمني لآخر الأحداث.
- تقرير يومي رسمي قابل للطباعة / الحفظ PDF.
- فحص اتصال n8n وإعادة بيانات التجربة من الموقع.

## لماذا النسخة مستقلة؟
هذه النسخة لا تستخدم:
- Google Sheets
- Supabase
- PostgreSQL
- أي Workflow سابق

بيانات التجربة تحفظ داخل **Workflow Static Data** في Workflow SchoolPulse نفسه.

## 1. تثبيت n8n
أنت لا تحتاج n8n جديدًا. استورد فقط:

`n8n/SchoolPulse_n8n_DEMO.json`

إلى n8n الموجود عندك.

الـWorkflow يأتي `Inactive` عند الاستيراد.

### لا يوجد تعارض مع الموجود
مسار الـWebhook الجديد هو:

`schoolpulse-api-v1`

أي:
`https://n8n.yasergrid.online/webhook/schoolpulse-api-v1`

ولا يستخدم أي Webhook من مشاريعك الأخرى.

## 2. مفتاح الدخول الافتراضي
للتجربة:

`SCHOOLPULSE-DEMO-1448`

لتغييره:
- افتح Workflow.
- افتح عقدة `SchoolPulse API Engine`.
- ابحث عن:
  `const API_KEY = 'SCHOOLPULSE-DEMO-1448';`
- ضع مفتاحًا جديدًا.
- Save.

الموقع لا يخزن المفتاح داخل الملفات. المستخدم يدخله في شاشة الدخول ويتم حفظه فقط في `sessionStorage` للمتصفح.

## 3. تفعيل Workflow
بعد الاستيراد:
1. Save.
2. Activate.
3. لا تستخدم Test URL في الموقع.
4. استخدم Production Webhook.

الموقع مجهز مسبقًا على:
`https://n8n.yasergrid.online/webhook/schoolpulse-api-v1`

إذا أردت دومينًا آخر عدل فقط:
`assets/config.js`

## 4. رفع الموقع
مجلد المشروع Static Site ويمكن رفعه على:
- Vercel
- Netlify
- GitHub Pages
- أي استضافة HTML

لـVercel:
1. ارفع محتويات ZIP إلى مستودع جديد.
2. Import Project في Vercel.
3. لا يوجد Build Command.
4. Root Directory = جذر المشروع.
5. Deploy.

## 5. أول تجربة
بعد فتح الموقع:
- مفتاح النظام: `SCHOOLPULSE-DEMO-1448`
- اسم الموظف: اكتب أي اسم تجريبي.

سيظهر Dashboard ببيانات جاهزة.

جرب:
1. أضف بلاغًا جديدًا.
2. سجل غياب معلم واكتب 3 حصص.
3. ستظهر 3 احتياجات تغطية جديدة.
4. أسند معلمًا بديلًا وغيّر الحالة إلى `مغطاة`.
5. أنشئ مهمة وأكملها.
6. سجل تأخر طالب.
7. افتح التقرير اليومي واطبعه PDF.

## التخزين الداخلي
التخزين يعتمد على:
`$getWorkflowStaticData('global')`

ومناسب لهذا **المشروع التجريبي**.

ملاحظة مهمة:
استخدم Workflow مفعّلًا وProduction Webhook حتى ترى سلوك الحفظ بين التنفيذات. لا تعتمد على الضغط المتكرر على Manual Test داخل محرر n8n لتقييم التخزين.
